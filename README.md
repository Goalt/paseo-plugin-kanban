# kanban-board — плагин Paseo

Родная kanban-доска внутри клиентов Paseo (браузер, desktop, mobile) поверх
[mcp-kanban](https://github.com/gablabelle/mcp-kanban), который крутится в контейнере
`mcp-hub`. Показывает и редактирует ровно те же данные, что агенты ведут через
MCP-инструменты хаба (`mcp__hub__kanban-*`), и обновляется сама, когда агент двигает
тикеты — без отдельного веб-UI на непроброшенном порту.

ТЗ проекта — `docs/SPEC.md`.

## Что умеет

- **Доска**: колонки горизонтальной лентой, карточки с `#номером`, приоритетом, меткой
  сессии и прогрессом сабтасков `n/m`; переключатель проектов; фильтр по сессии;
  счётчик «в работе».
- **Live-обновление**: изменения агентов появляются на доске за ~2 с без действий
  пользователя.
- **Детали тикета** (модалка): описание, колонка, сессия, сабтаски, зависимости,
  имена вложений.
- **CRUD с доски**: создание из колонки («+»), редактирование title/description/priority,
  перемещение (◀ ▶ и выбор колонки), сабтаски (создание и завершение), удаление с
  подтверждением.
- **Устойчивость**: недоступный API → экран «Доска недоступна» + Retry; борду плагин
  поднимает сам; выбранный проект переживает перемонтирование поверхности и reload.

## Точки входа

- пункт **Kanban** в сайдбаре (surface `main`);
- вкладка **Kanban** в воркспейсе и эксплорере (workspace panel `board`);
- **Open Kanban board** в Command Center (Ctrl+K).

## Архитектура

```
Paseo client (браузер / desktop / mobile)
   └─ board.client.tsx ── useRpc ──►  index.ts (сервер плагина в демоне)
        ticket-modal.client.tsx           ├─ REST  http://mcp-hub:3010/api/*
        ticket-form.client.tsx            ├─ WS    ws://mcp-hub:3010/ws  (version++)
        toast.client.tsx                  ├─ docker exec — автостарт борды
        mutations.client.ts               └─ память выбранного проекта
        ui.client.ts
```

| Файл | Роль |
| --- | --- |
| `index.ts` | точка входа: 12 RPC-обработчиков + регистрация поверхностей |
| `contract.ts` | zod-схемы и `defineRpc` — общий контракт клиента и сервера |
| `kanban-api.server.ts` | HTTP к REST mcp-kanban, сборка снапшота, мутации |
| `kanban-live.server.ts` | подписка на `/ws`, версия доски, реконнект |
| `kanban-autostart.server.ts` | подъём борды через `docker exec`, если API молчит |
| `plugin-state.server.ts` | последний выбранный проект (память процесса + файл) |
| `board.client.tsx` | доска, поллинг версии, фильтры, состояния |
| `ticket-modal.client.tsx` | детали тикета, редактирование, сабтаски, удаление |
| `ticket-form.client.tsx` | форма создания тикета, выбор приоритета |
| `toast.client.tsx`, `mutations.client.ts`, `ui.client.ts` | тост, раннер мутаций, общие стили |

**Live-обновления.** RPC в 0.6.1 — только запрос-ответ, push с сервера в клиент нет.
Поэтому сервер плагина держит WebSocket к kanban и на каждое событие увеличивает
`version`, а клиент раз в 2 с спрашивает `kanban.version` (ответ из памяти, без REST) и
перезабирает снапшот только при росте номера. При обрыве WS — реконнект с бэкоффом
1→30 с, при переподключении `version++` (за время простоя могли пропустить события).

**RPC:** `kanban.snapshot`, `kanban.version`, `kanban.projects`, `kanban.ticket`,
`kanban.ticket.move/create/update/delete`, `kanban.subtask.create/complete`,
`kanban.state.get/set`. Все ответы — `{ok, error, …}`, исключения наружу не летят.

## Установка

```bash
npm install
npm run typecheck
paseo plugin install /home/devuser/paseo-plugins/kanban-board   # первый раз
paseo plugin reload kanban-board                                # после правок
paseo plugin ls        # → running
paseo plugin logs kanban-board
```

## Переменные окружения демона

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `KANBAN_URL` | `http://mcp-hub:3010` | адрес API kanban. IP не хардкодим: имя контейнера резолвится DNS docker-сети, IP меняется при пересоздании |
| `KANBAN_CONTAINER` | `mcp-hub` | контейнер для автостарта борды; если `KANBAN_URL` указывает не на него, автостарт пропускается |
| `KANBAN_STATE_FILE` | `~/.paseo-kanban-board.json` | где хранится последний выбранный проект |

## Ограничения Paseo 0.6.1 (проверены на этом демоне)

1. **Никакого `async`/`await` в клиентских файлах.** Компилятор 0.6.1 собирает клиентский
   бандл с `target: es2020` и не понижает асинхронный синтаксис; Metro делает это для кода
   приложения, но бандлы плагинов идут мимо Metro, поэтому Hermes на iOS/Android молча не
   грузит плагин. Только промис-цепочки. Проверка перед сдачей:
   `grep -nE "async|await" *.client.tsx *.client.ts` — должно быть пусто.
2. **Импорты клиента — только `react`, `react-native`, `@getpaseo/plugin`.** Всё остальное
   в клиентском бандле внешнее и не резолвится.
3. **Точка входа — `index.ts`** (не `index.client.tsx` из v0.8). Разделение по суффиксам
   `*.client.*` / `*.server.*`: импорт серверного модуля вырезается из клиентского бандла,
   а попытка импортировать его из клиентского файла — ошибка сборки.
4. **Имена RPC — только нижний регистр**, `/^[a-z][a-z0-9._-]*$/`. `kanban.moveTicket`
   роняет плагин на загрузке («Invalid plugin RPC method»); отсюда `kanban.ticket.move`.
5. **Палитра темы — ровно шесть цветов**: `surface0`, `foreground`, `foregroundMuted`,
   `accent`, `accentForeground`, `statusDanger` (`toPluginTheme` в клиенте демона).
   Отдельного `warning` нет, поэтому приоритеты различаются ещё и заливкой, а
   «заблокирован» у зависимостей красится в `statusDanger`.
6. **У пунктов сайдбара и панелей нет бейджа.** `addSidebarItem` в клиенте демона
   пересобирает вклад из `{id, title, icon, surface}` — лишние поля теряются. Поэтому
   счётчик «в работе N» живёт в шапке доски, а не у пункта сайдбара.
7. **Drag&drop не делаем**: кросс-платформенного DnD в клиентском рантайме плагинов нет
   (открытая issue апстрима #3558). Перемещение — кнопками ◀ ▶ и выбором колонки.
8. **Хранилища состояния у клиента нет** — выбранный проект помнит сервер плагина.
9. Плагины поддерживаются клиентами Paseo с 0.5.0; нативный путь на iOS починен в 0.7.0,
   клиент 0.4.0 про плагины не знает.

## Отличия от родного web-UI mcp-kanban

| Родной web-UI | Этот плагин | Почему |
| --- | --- | --- |
| сабтаски спрятаны внутрь истории | сабтаски — обычные карточки с пометкой `↳ #родитель` | агенты двигают именно сабтаски; прятать их — врать про состояние доски |
| drag&drop колонок и карточек | кнопки ◀ ▶ и выбор колонки в модалке | см. ограничение 7 |
| markdown в описании | плоский текст | сторонние библиотеки в клиентском бандле недоступны |
| просмотр вложений | только имена файлов | вне рамок v1 (ТЗ §6) |
| создание/удаление проектов, правка колонок, управление сессиями | только просмотр и переключение | вне рамок v1 (ТЗ §6) |
| порядок карточек внутри колонки перетаскиванием | тикет уезжает в конец целевой колонки | `order` не редактируем (ТЗ §6) |

Прогресс сабтасков `n/m` плагин считает сам: листинг `GET /api/tickets` отдаёт голые
тикеты без `subtask_total/completed` — они есть только в `GET /api/tickets/:id`.
Колонки берём из `GET /api/projects/:id/columns`: `GET /api/columns?project_id=…` в
mcp-kanban не существует и проваливается в SPA-фолбэк, отдавая **HTML с кодом 200**.

## Разработка

```bash
npm run typecheck
node dev/rpc-smoke.mjs                # чтение: снапшот, версия, проекты
node dev/rpc-smoke.mjs --mutations    # полный CRUD-цикл в проекте plugin-sandbox
FIXTURE='<json снапшота>' node dev/render-test.mjs           # клиент в jsdom
THEME=light COMPACT=1 DUMP=/tmp/x.html node dev/render-test.mjs   # HTML для скриншота
```

`dev/rpc-smoke.mjs` компилирует плагин **тем же компилятором, что и демон**, поднимает
серверный бандл в процессе и валидирует ответы zod-схемами контракта; мутации он гоняет
только в проекте `plugin-sandbox` и отказывается работать с любым другим.
`dev/render-test.mjs` рендерит клиентский бандл в jsdom через react-native-web
(зависимости ставятся разово: `npm install --no-save react-dom@19.1.0 react-native-web jsdom`).

## План миграции на Paseo v0.8

1. Точка входа переезжает в `index.client.tsx` + каталог `client/`; текущее разделение по
   суффиксам `.client`/`.server` останется совместимым ориентиром.
2. `Modal`, `ScrollView`, `TextInput` берутся из `@getpaseo/plugin/react-native` вместо
   `react-native`; собственный `TicketModal` можно заменить на `Modal.Content` из SDK.
3. Компилятор 0.7.0+ понижает асинхронный синтаксис (`supported: { "async-await": false }`,
   PR #3942) — запрет на `async`/`await` в клиенте снимается, промис-цепочки можно
   постепенно распутать.
4. Если в 0.8 появится push с сервера в клиент — поллинг `kanban.version` заменяется
   подпиской, `version` остаётся как маркер изменений.
5. Появится бейдж у пунктов сайдбара — счётчик «в работе» переезжает туда (см. #31).
6. Появится DnD — кнопки ◀ ▶ остаются как доступная альтернатива, добавляется
   перетаскивание и правка `order`.

## Репозиторий

Эталон истории — **локальный git-репозиторий на VPS** (`~/paseo-plugins/kanban-board`),
коммиты по сабтаскам спринтов. Публикация в приватный GitHub-репозиторий
`paseo-plugin-kanban` — отдельная задача (#34), выполняется отдельно; видео в репозиторий
не кладём.
